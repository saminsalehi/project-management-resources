# Project Kickoff Checklist

*Samin Salehi, PMP ([ORCID](https://orcid.org/0009-0005-4143-2816)) · Project Manager Land · Based on [The Five Project Management Basics](../guides/02-five-project-management-basics.md)*

Run through this list before work begins. Each unchecked box is a gap that could stall the project later.

## 1. Goal
- [ ] We can answer **why** we are doing this project
- [ ] The required **result** is written in one or two sentences
- [ ] We agree how we'll know it's **done well** (acceptance criteria)
- [ ] The sponsor or owner has confirmed the goal

## 2. Scope
- [ ] Key deliverables are listed
- [ ] What is **out of scope** is written down
- [ ] The people who approve deliverables have agreed to the scope
- [ ] Deliverables are broken into smaller tasks (a WBS)

## 3. Plan and schedule
- [ ] Tasks are in order and **dependencies** are identified
- [ ] Durations are estimated (use three-point estimates for uncertain tasks)
- [ ] Key dates and milestones are on the schedule
- [ ] The **critical path** is known
- [ ] Long-lead items and approvals are flagged early

## 4. People
- [ ] Every task has a named owner
- [ ] Decision-makers and approvers are named (a [RACI](../templates/raci-matrix.csv))
- [ ] Stakeholders are listed with their interests ([Stakeholder Register](../templates/stakeholder-register.csv))
- [ ] The communication rhythm is agreed (who gets what update, when, and how)

## 5. Risk and change
- [ ] The first risks are in the [Risk Register](../templates/risk-register.csv), each with an owner
- [ ] The change process is agreed ([Change Request](../templates/change-request.md))
- [ ] Issue escalation path is agreed

## 6. Kickoff meeting
- [ ] Goal, scope and exclusions are presented
- [ ] Schedule and milestones are reviewed
- [ ] Roles are confirmed
- [ ] Top risks are discussed
- [ ] Next steps and the date of the first status update are set
